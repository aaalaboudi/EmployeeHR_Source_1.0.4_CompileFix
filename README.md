# EmployeeHR 1.0 — إدارة الموظفين والإجازات والتصفية النهائية

تطبيق Windows Desktop عربي مبني باستخدام **C# / .NET 8 LTS / WPF / SQLite** لمنشأة صغيرة حتى نحو 100 موظف. صُمم ليعمل كنسخة Portable من مجلد محلي أو USB/External SSD دون Setup، ودون Registry، ودون صلاحيات Administrator، ودون الحاجة إلى تثبيت .NET Runtime أو SQLite على جهاز المستخدم النهائي بعد نشر النسخة Self-Contained.

## هيكل النسخة المحمولة

عند أول تشغيل لـ `EmployeeHR.exe` يستخدم التطبيق `AppContext.BaseDirectory` فقط، وينشئ تلقائيًا:

```text
EmployeeHR_Portable\
  EmployeeHR.exe
  EmployeeHR.db
  Backups\
  Exports\
```

لا توجد مسارات ثابتة ولا يعتمد التطبيق على حرف القرص؛ يمكن نقل المجلد من `D:\` إلى `E:\` أو أي موقع قابل للكتابة، وتنتقل قاعدة البيانات معه.

## الوحدات المنفذة

- لوحة معلومات: أعداد الموظفين، العقود والإقامات القريبة من الانتهاء، الإجازات الحالية والقادمة، إجمالي الأرصدة، الأرصدة المرتفعة، ومن يقترب من إكمال خمس سنوات.
- الموظفون: بيانات الهوية والإقامة والجنسية والوظيفة والقسم وبداية العمل والحالة والعقد وفترة التجربة والملاحظات، مع Unique Constraint لرقم الموظف والهوية/الإقامة.
- العقود: سجل تاريخي مستقل بعمر سريان `Effective From / Effective To`.
- الرواتب: جميع المكونات المطلوبة مع `Salary History` وعدم استبدال الرواتب القديمة، وإعداد مستقل لدخول كل مكون في EOSB/الإجازة/الحسابات الأخرى.
- الإجازات السنوية: مسودة/معتمدة/ملغاة، Calendar Days أو Working Days، وعطلة نهاية أسبوع قابلة للتعديل (الافتراضي Friday/Saturday).
- سجل الإجازة: رصيد افتتاحي + استحقاق Pro-Rata + استخدام + تعديلات، مع إعادة بناء الحركات النظامية وإظهار الرصيد الجاري.
- الإجازات دون أجر: معالجة مستقلة لكل حالة لأثرها على مدة الخدمة، استحقاق الإجازة، ووقف العقد.
- قواعد نظامية مؤرخة: Leave Rules / EOSB Rules / Resignation Rules مع `Effective From / Effective To`.
- مدة الخدمة: إجمالي الأيام، الأيام المستبعدة، الصافي، سنوات/أشهر/أيام، ورقم عشري دون تقريب لسنة كاملة.
- مكافأة نهاية الخدمة: محرك مستقل يعرض الأجر المؤهل والمكونات الداخلة والخارجة، أول خمس سنوات، ما بعدها، النسبة، والنتيجة.
- انتهاء الخدمة: السبب، الطرف، المادة، نوع العقد، وتعويض إنهاء العقد كعنصر مستقل لا يُفترض تلقائيًا. يتضمن زرًا اختياريًا لاحتساب استرشادي للمادة 77 لا يعمل إلا بطلب المستخدم، ويترك النتيجة للمراجعة والحفظ.
- التصفية النهائية: راتب الشهر الأخير حتى آخر يوم، EOSB، قيمة رصيد الإجازة، التعويض، مستحقات إضافية، خصومات، وصافي التصفية مع تفاصيل المعادلات.
- التقارير: Employees / Leave Balance / Leave Transactions / Unpaid Leave / Salary History / EOSB / Final Settlement / Audit / Contract Expiry / Iqama Expiry.
- التصدير: XLSX حقيقي، PDF محلي يحافظ على العربية بصريًا، وطباعة Windows.
- كشف تصفية عربي: الاسم، الهوية/الإقامة، بداية ونهاية الخدمة، المدة، الأجر، الرصيد وقيمته، EOSB، التعويض، الخصومات، الصافي، تاريخ الإعداد، وتوقيعا الموظف والمسؤول.
- النسخ الاحتياطي: عند بدء/إغلاق البرنامج، يدويًا، واستعادة نسخة؛ مع سياسة احتفاظ قابلة للتعديل.
- Audit Log: المستخدم في Windows، الجهاز، الوقت، العملية، الكيان والتفاصيل.

## القواعد النظامية الافتراضية

تمت تهيئة القواعد الافتراضية على أساس مواد نظام العمل السعودي ذات العلاقة، مع إبقاء القواعد قابلة للتعديل والتأريخ داخل قاعدة البيانات. من أهم المراجع: المواد 54، 77، 80، 84، 85، 86، 87، 88، 109، 116. المرجع الحكومي: وزارة الموارد البشرية والتنمية الاجتماعية — صفحة علاقات العمل.

> التطبيق أداة حساب وإدارة وليس فتوى أو رأيًا قانونيًا. بعض الحالات تعتمد على نص العقد وسبب الإنهاء والوقائع والاتفاقات والاستثناءات النظامية؛ لذلك تُعرض المواد والمعادلات ويُترك للمستخدم توثيق المعالجة الصحيحة للحالة.

## إنشاء EmployeeHR.exe على Windows

الحزمة المصدرية تحتوي على:

- `Build-Portable.cmd`
- `Build-Portable.ps1`

على جهاز Windows 10/11 x64 متصل بالإنترنت لأول عملية بناء فقط، شغّل `Build-Portable.cmd`. إذا لم يكن .NET 8 SDK موجودًا، يقوم السكربت بتنزيل **SDK محلي داخل مجلد المشروع فقط** دون Administrator ودون تثبيته على النظام، ثم ينفذ `dotnet publish` ويُنشئ:

```text
Release\EmployeeHR_Portable\EmployeeHR.exe
Release\EmployeeHR_Portable.zip
```

بعد ذلك لا يحتاج **جهاز المستخدم النهائي** إلى SDK أو Runtime أو Setup أو إنترنت.

## ملاحظات تشغيل مهمة

1. يجب وضع `EmployeeHR.exe` في مجلد يمكن للمستخدم الكتابة فيه؛ لا تضعه في `Program Files` إذا كان الحساب لا يملك صلاحية الكتابة.
2. لا تفصل USB أثناء حفظ البيانات أو إنشاء نسخة احتياطية.
3. احتفظ بنسخ احتياطية دورية خارج نفس USB تحسبًا للتلف أو الفقد.
4. التواريخ تحفظ في SQLite بصيغة Gregorian ISO `yyyy-MM-dd` لتجنب تغير المعنى بين أجهزة ذات إعدادات تقويم مختلفة.
5. النسخة الحالية تستهدف `win-x64`، وهو الأنسب لمعظم أجهزة Windows 10/11. يمكن تغيير Runtime في سكربت البناء إذا لزم ARM64.
